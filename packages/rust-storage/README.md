# Persistencia local CHEF

Adaptador Rust para guardar/recuperar snapshots CHEF `1.0.0` y `1.1.0` en SurrealDB embebida con RocksDB, bajo su `runId` determinista. Para las importaciones JSONL heredadas guarda en un único upsert el snapshot, los eventos fuente completos y el grafo CHEF 1.4.0 (también lee 1.0.0–1.3.0): activos tipados, evidencia, relaciones observadas o sugeridas y conteo de tipos aún no adaptados. Las respuestas archivadas de Censys y urlscan se guardan aparte en `provider_imports`, con ID determinista, hash de respuesta, eventos fuente y grafo CHEF. Esta separación conserva el significado de Snapshot, que representa observaciones, no pistas históricas del proveedor. Depende de `chef-core`, no al revés; la composición de escritorio entrega la ruta de datos desde Tauri.

Cada importación se valida antes de persistir: dominio/IP, hash SHA-256, IDs, grafos y proyección determinista. La lectura vuelve a verificar la identidad y versión del registro. Las importaciones urlscan admiten hasta 2 MiB y se guardan fuera de Snapshot porque sus nombres/orígenes son pistas históricas, no DNS actual. Los datos se guardan localmente; no se consulta Censys/urlscan ni se hace DNS/HTTP. Los resúmenes IPC tienen [esquema Censys](../../docs/contracts/censys-ip-import.schema.json), [ejemplo Censys](../../docs/contracts/examples/censys-ip-import.json), [esquema urlscan](../../docs/contracts/urlscan-import.schema.json) y [ejemplo urlscan](../../docs/contracts/examples/urlscan-import.json); el chequeo documental valida los ejemplos. La búsqueda vectorial se decidirá solo si las métricas lo requieren.

```powershell
cargo test --manifest-path packages/rust-storage/Cargo.toml --locked
```

SurrealDB queda fijada en `Cargo.toml` y `Cargo.lock`; el motor RocksDB está embebido y persiste en un directorio, no requiere un servidor aparte. El spike de producción debe evaluar migraciones, backup/restauración, recuperación tras cierre inesperado, bloqueo del directorio, tamaño de instalador y compatibilidad en cada sistema operativo. En Windows el build de RocksDB requiere NASM, CMake, toolchain nativo y libclang; el entorno CHEF ya tiene estas herramientas instaladas en el perfil local, pero cada CI/estación de desarrollo debe documentar su propia configuración.
