# Plan de migración del backend a Rust

Actualizado 27-10-2026. **Programa iniciado; migración incompleta.** La fuente local analizada declara la versión 3.0.2. El inventario reproducible contiene 466 archivos Python y 97 533 líneas: 251 archivos de implementación (51 219 líneas), 215 archivos de prueba (46 314 líneas) y 176 módulos, incluidas las salidas. La copia no incluye historial Git que permita separar modificaciones privadas. CHEF adoptó AGPL-3.0-only por decisión explícita del propietario; la atribución y licencia de la fuente se conservan en [avisos de terceros](../../THIRD_PARTY_NOTICES.md). Véanse el [inventario por archivo](inventario-migracion.csv) y la [auditoría](auditoria-fuente.md).

CHEF mantiene la dirección de escritorio Rust/Tauri y no incorpora Go. El objetivo es migrar a Rust las capacidades que aporten valor al reconocimiento y a la revisión de evidencia CHEF; no se trasladará un modelo genérico sin adaptación de producto. La equivalencia funcional completa todavía no existe. Cada subsistema útil debe tener una adaptación CHEF concreta o una exclusión justificada. El parser offline admite el formato JSONL, conserva UUID, `data_json`, marcas de tiempo y linaje, y redacta secretos y credenciales de URL. `recon.rs` produce activos CHEF tipados (dominio, IP, servicio, endpoint, tecnología, certificado y candidato de hallazgo) con evidencia y relaciones sustentadas; los hallazgos permanecen como candidatos. Los eventos fuente se conservan para que los tipos pendientes no se pierdan. El snapshot interoperable correlaciona `OPEN_TCP_PORT` y `OPEN_UDP_PORT` en versión 1.1.0. El motor Rust admite módulos registrados, expansión recursiva, deduplicación y límites; el importador Tauri ejecuta las transformaciones locales solo cuando se habilitan en `config.toml`, apagadas por defecto. No ejecuta módulos DNS/HTTP ni consultas pasivas. Las pruebas funcionales se realizarán en la fase posterior indicada por el propietario.

## Fases de migración

1. **Inventario de equivalencia:** registrar cada módulo, evento, helper, preset, salida y prueba de origen con su función y destino CHEF; no dar por completo el port hasta resolver cada elemento.
2. **Contratos y motor de eventos:** mapear eventos de origen al modelo CHEF, portar dispatcher, ejecución recursiva compatible, cancelación, límites y deduplicación; el importador de puertos es solo el primer corte.
3. **Capacidades de reconocimiento:** portar los módulos DNS, HTTP, TLS y pasivos presentes en el inventario que sean compatibles con CHEF, detrás de adaptadores Rust. Preparar pruebas offline; mantener ejecución de red apagada hasta autorización.
4. **Aplicación y persistencia:** integrar React/Tauri, Tokio, eventos de terminal y SurrealDB/RocksDB; migrar configuración y flujos CLI a CHEF sin cargar plugins Python ni instalar herramientas externas automáticamente.
5. **Salidas, presets y recursos:** adaptar salidas al snapshot CHEF e integraciones requeridas; reconstruir presets/recursos con procedencia clara y permisos explícitos.
6. **Pruebas y retiro:** reconstruir en Rust la cobertura de las 215 pruebas Python relevantes mediante fixtures/golden CHEF; retirar referencias solo después de paridad funcional, revisión humana y resolución de licencias.

## Criterio de terminado por componente

Dado cada elemento del inventario de origen, cuando finaliza la migración, entonces tiene implementación Rust CHEF con prueba equivalente o una exclusión justificada y documentada; el estado parcial actual no se presenta como portado completo. Un motor activo solo se ejecuta tras el gate de autorización independiente. Cada tarea incluye prueba, documentación, procedencia y verificación dentro de CHEF.

El README principal conserva la referencia de uso y procedencia. El árbol fuente local permanece intacto; la atribución y las obligaciones AGPL-3.0 se registran en los avisos de terceros. El inventario no afirma equivalencia funcional: actualmente 24 archivos están parciales, 421 siguen pendientes y 21 se excluyeron con motivo documentado, de 466 listados; cada capacidad debe implementarse, adaptarse o excluirse con motivo CHEF documentado.
