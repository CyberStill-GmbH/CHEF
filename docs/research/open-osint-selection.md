# Selección de OSINT abierta para CHEF

Consulta de fuentes primarias: 29-09-2026. **Decisión de investigación, no conectores implementados ni acceso probado con credenciales.** “Open source” califica la licencia del _software_; “dato público” y “API sin clave” son propiedades distintas y no autorizan republicar resultados o consultar objetivos de clientes. No se realizaron consultas de reconocimiento. El catálogo de URLs, versión y límites está en [sources.json](sources.json).

## Recomendación de primera vertical

**1. Nmap XML autorizado + una fuente pasiva con procedencia por registro.** El fixture Nmap es la única entrada garantizada hoy. Para un conector directamente accesible, **Common Crawl Index** es el candidato abierto más verificable: [los datos son de acceso gratuito](https://commoncrawl.org/get-started) y su [servidor de índice publica una API CDX](https://index.commoncrawl.org/). Puede aportar URL/hostname y fecha de captura. Es cobertura parcial e histórica: una URL indexada no prueba que el host ni el puerto sigan vivos, ni que pertenezcan al cliente. Una relación con Nmap será `candidate` hasta corroboración de identidad/tiempo. Sus [términos](https://commoncrawl.org/terms-of-use/full/) deben comprobarse para el uso y retención concretos.

**2. RDAP como contexto de registro, no fuente de servicios.** [RFC 9083](https://www.rfc-editor.org/rfc/rfc9083.html) define JSON y [IANA publica bootstrap](https://www.iana.org/assignments/rdap-dns) para localizar servidores por TLD. Puede contextualizar dominio/registro, pero respuestas redactadas, límites por operador y fechas heterogéneas impiden usarlo como prueba de propiedad de un host. Priorizarlo después de una fuente que realmente enlace con el Nmap disponible.

**3. CT como descubrimiento histórico de nombres.** [RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html) define logs públicos; el código de [crt.sh](https://github.com/crtsh/certwatch_db) es abierto, pero la existencia de un sitio público no equivale a un contrato de API de búsqueda con capacidad garantizada. CHEF puede importar un export/fixture de CT con origen/fecha y estudiar conector tras verificar términos y límites del operador. Certificado y SAN no prueban servicio actual ni identidad de IP.

**4. Subfinder/Amass como importación opcional, no dependencia central.** [Subfinder](https://github.com/projectdiscovery/subfinder) es MIT y funciona sin claves para algunas fuentes, pero su README advierte que muchas fuentes requieren API keys y su [disclaimer](https://github.com/projectdiscovery/subfinder/blob/dev/DISCLAIMER.md) remite a términos de terceros. [OWASP Amass](https://github.com/owasp-amass/amass) es software abierto con modos pasivo/activo; la configuración y subcomponentes deben revisarse por versión. Un adaptador de salida con origen por hallazgo puede ser útil. No ejecutar sus modos activos desde CHEF en la fase actual ni considerar un agregado de fuentes como procedencia única.

## Fuentes a evaluar más tarde

- [Shodan API](https://developer.shodan.io/api), [Censys Platform API](https://docs.censys.com/docs/platform-api-transition-guide) y [VirusTotal relationships](https://docs.virustotal.com/reference/domains-relationships) pueden aportar servicios o vínculos, pero **no son “open source” por ofrecer API**. Requieren cuenta/clave, cuotas o condiciones particulares; no se han comprobado acceso ni licencia para CHEF. Esas fuentes podrían mejorar corroboración temporal de servicio, especialmente para IP/puerto, pero jamás se incorporan por defecto.
- Capturas HTTP propias y autorizadas son una segunda clase de evidencia pasiva valiosa. El spike Montoya actual solo produce un envelope separado; falta adaptador al núcleo y contrato de enlace.
- DNS activo, resolución de nombres, crawls, port scans o consultas a objetivos no forman parte de la fase de importación aprobada. Ni Subfinder ni Amass deben ejecutarse en modo que los active sin una decisión de scope.

## Criterio de selección verificable

Puntuar cada candidato **antes** de integrar: permiso/términos de uso, acceso reproducible, fuente y timestamp por resultado, utilidad para enlace con Nmap, frescura, estabilidad/versionado, cuota/coste y capacidad de crear un fixture libre de datos de clientes. Un proveedor sin permiso, fuente por registro o fixture tiene gate fallido. En empate, preferir API documentada y un adaptador pequeño a un wrapper de “todo OSINT”. Registrar error, truncación, cuota agotada y fecha de última consulta en la UI; ningún fallo de proveedor debe parecer “no existe activo”.

Para la demo de octubre, el fixture actual usa `.invalid` y loopback, de modo que **no puede corresponder honestamente a una respuesta viva de Common Crawl, CT o RDAP**. Crear un fixture pasivo sintético con etiquetas y procedencia simulada es útil para probar el algoritmo, pero no valida una fuente real. Un experimento real requiere un dominio/dataset autorizado que corresponda al Nmap importado, términos revisados y acceso probado. Esto es la dependencia de producto más importante que falta.

La ventaja competitiva no consiste en agregar el mayor número de fuentes: [Amass](https://github.com/owasp-amass/amass), [Subfinder](https://github.com/projectdiscovery/subfinder), [SpiderFoot](https://github.com/smicallef/spiderfoot) y [Uncover](https://github.com/projectdiscovery/uncover) ya cubren agregación. CHEF debe demostrar que reduce pasos/errores al **explicar la fusión, la contradicción y la limpieza**, con prueba controlada descrita en el [estudio de correlación](recon-correlation-2026-09.md).
