# Fuentes OSINT seleccionadas para CHEF

Selección de producto fechada 29-09-2026; fuentes primarias en [sources.json](sources.json). **Se eligió el orden de integración, no se implementó ningún conector ni se verificó acceso para un objetivo de cliente.** “Software open source”, “datos públicamente consultables”, “uso gratuito” y “permiso de reutilización” son cuatro propiedades diferentes. CHEF consultará solo identificadores incluidos en un scope aprobado, con egress de la API Node, nunca desde el navegador ni desde Go. Cada resultado conserva proveedor, consulta, locator, tiempo de observación, tiempo de ingesta, límites y términos aplicables.

## Orden elegido

**Decisión de primera vertical:** implementar como máximo **Common Crawl Index** después de confirmar términos y un dominio de prueba autorizado que tenga XML Nmap correspondiente. RDAP y RIPEstat son los dos conectores siguientes, **no requisitos simultáneos de octubre**. CT queda como importación reproducible hasta verificar un acceso de búsqueda mantenible. Los cuatro producen señales distintas y no se suman como votos independientes sobre “propiedad”: una URL histórica, registro RDAP y anuncio de prefijo pueden coexistir con una IP compartida.

## Opcionales descartados del corte inicial

[urlscan.io permite buscar escaneos existentes](https://urlscan.io/docs/api/) por dominio/IP y devuelve evidencia web más cercana a un servicio, pero exige cuenta/API key para uso fiable; desde mayo de 2026 ciertos endpoints requieren autenticación. Sus [términos](https://urlscan.io/terms/) restringen uso comercial/agregación y el envío de URLs puede publicar información. **No incluirlo por defecto** ni enviar objetivos; evaluar solo tras autorización y revisión de licencia. [Shodan](https://developer.shodan.io/api), [Censys](https://docs.censys.com/docs/platform-api-transition-guide) y [VirusTotal](https://docs.virustotal.com/reference/domains-relationships) podrían corroborar servicios con más precisión, pero planes, claves, cuotas y derechos de uso no están confirmados; no son fuentes abiertas por ofrecer API. [Subfinder](https://github.com/projectdiscovery/subfinder) y [OWASP Amass](https://github.com/owasp-amass/amass) son software abierto, no una licencia única sobre todas sus fuentes. CHEF podrá importar sus salidas con procedencia por proveedor después; no ejecutará modos activos en esta fase.

## Lo que estas fuentes permiten afirmar

Nmap aporta una observación autorizada de IP/protocolo/puerto/estado en un momento; Common Crawl aporta URL histórica; RDAP, contexto de registro; RIPEstat, contexto de enrutamiento; CT, nombres de certificados. Una coincidencia de hostname, IP, ASN, banner o certificado puede producir una **relación candidata explicada**, no una fusión automática de activos ni una vulnerabilidad. Para validar un vínculo fuerte con el **mismo servicio**, usar un segundo registro autorizado con endpoint tipado y tiempo compatible (por ejemplo, una captura HTTP propia/importada con permiso), más control negativo de IP compartida. El [motor Go propuesto](../adr/0011-node-go-boundary.md) conserva las observaciones y devuelve regla, versión, evidencia y grado de certeza; no consulta OSINT ni amplía scope.

El fixture Nmap actual usa loopback y `.invalid`: ninguna fuente pública devolverá honestamente esa pareja. Un fixture pasivo sintético etiquetado prueba algoritmo/UI, **no cobertura ni exactitud de OSINT real**. El gate para ensayo real exige dominio o IP de prueba autorizado, XML Nmap correspondiente, permiso para consulta a cada proveedor, términos/retención aceptados, fecha, cuota observada y evaluación de falsos enlaces. No se ejecutó reconocimiento para redactar esta selección.

## Contrato operativo por adaptador

Cada conector debe registrar versión de API, URL fija/allowlist de destino, scope de consulta, cache/TTL, cuota, backoff ante 429, timeout, paginación y truncación, estado parcial y fecha de última actualización. No aceptar una URL arbitraria del usuario como destino de fetch (riesgo [CWE-918](https://cwe.mitre.org/data/definitions/918.html)). La UI distingue “sin resultados”, “consulta no realizada”, “fuente indisponible”, “truncada” y “datos históricos”. Se conserva respuesta mínima necesaria o digest/locator según licencia y política de retención. Cada proveedor tiene fixtures positivos/negativos y revisión de términos antes de mover su issue a `Ready`.

La hipótesis diferencial de CHEF sigue siendo **menos pasos y menos enlaces erróneos para justificar una superficie de ataque**, no “más APIs”. [Amass](https://github.com/owasp-amass/amass), [Subfinder](https://github.com/projectdiscovery/subfinder) y [SpiderFoot](https://github.com/smicallef/spiderfoot) ya agregan fuentes; CHEF debe medir tiempo, pasos, errores y falsos enlaces contra revisión manual con el mismo dataset, como describe el [estudio de correlación](recon-correlation-2026-09.md).
