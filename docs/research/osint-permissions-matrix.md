## Por qué existe esta matriz

“Datos públicamente consultables”, “API gratuita”, “software open source” y “permiso para reutilizar y retener” son cuatro propiedades distintas. Una fuente puede permitir consultar un dominio y prohibir agregarlo, o permitir el acceso manual y exigir clave para automatizarlo. CHEF no debe confundir esas capas: cada conector necesita una decisión registrada por fuente, con fecha, términos y responsable.

La matriz **no autoriza** ninguna consulta ni sustituye la revisión legal. Tampoco convierte una fuente en “aprobada” por aparecer en `sources.json`: ese registro prueba que se consultó documentación pública el 29-09-2026, no que exista acceso para un objetivo de cliente.

## Reglas comunes propuestas (no verificadas)

- **Scope primero.** Toda consulta usa identificadores de un scope aprobado. Un archivo importado, una URL o un ASN no amplían el scope.
- **Egress solo desde la API Node.** Nunca desde el navegador ni desde el motor Go, y nunca con una URL arbitraria elegida por el usuario (riesgo [CWE-918](https://cwe.mitre.org/data/definitions/918.html)).
- **Allowlist por proveedor.** Host, ruta y parámetros fijos; timeout, cuota, backoff ante 429, paginación y truncación declarados por adaptador.
- **Estados honestos.** La UI distingue “sin resultados”, “consulta no realizada”, “fuente indisponible”, “truncada” y “dato histórico”. Un fallo del proveedor nunca se muestra como cero hallazgos.
- **Mínimo dato.** Se conserva lo necesario para explicar el enlace: proveedor, consulta, locator, digest, fecha de observación e ingesta, límites. El raw solo con habilitación explícita del proyecto y política de retención decidida.
- **Sin reidentificación.** No se envían datos de clientes a terceros por defecto; no se publican capturas, tokens ni URLs sensibles en Git.

## Qué falta para mover una fila a `prueba`

1. Dominio o IP de prueba autorizado por su propietario, con XML Nmap correspondiente cuando se quiera correlacionar.
2. Términos y política de retención leídos en su versión vigente, con fecha y responsable registrados.
3. Permiso de consulta comprobado (cuenta, clave o acceso público real) y cuota observada.
4. Fixture positivo y negativo, más un control negativo de IP compartida para no fusionar activos.
5. Revisión de otra persona del equipo y nota de compatibilidad si el contrato cambia.

## Lo que esta matriz no decide

No elige el proveedor definitivo, no fija precios ni cuotas, no sustituye una revisión legal y no afirma que CHEF tenga hoy conectores OSINT. El adaptador de Common Crawl existe y se prueba con un fixture CDX sintético; eso valida el algoritmo y el etiquetado `passive-signal`, **no** el acceso a la fuente ni su exactitud.
