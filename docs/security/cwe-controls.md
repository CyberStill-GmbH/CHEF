# Debilidades CWE y criterios de seguridad de CHEF

Fecha 29-09-2026. [CWE de MITRE](https://cwe.mitre.org/) clasifica clases de debilidad; **no es un proceso de arquitectura ni una certificación**. Esta matriz conecta fronteras C4 con controles y pruebas. [OWASP ASVS](https://owasp.org/projects/asvs) proporciona requisitos de verificación de aplicación web; aplicar una revisión por control cuando se construya API/UI. Estado `actual` significa que existe código/prueba indicada, `propuesto` que todavía no se puede afirmar mitigación.

**Amenazas de integridad semántica** como falso enlace o atribución de vulnerabilidad no se reducen a un CWE único. Se tratan con identidad tipada, observaciones inmutables, control negativo, regla versionada y evaluación de falsos positivos. No usar un número CWE como prueba de que el control existe. El [modelo de amenazas](threat-model.md) conserva abuso/activos y debe actualizarse cuando se añada PostgreSQL, OAuth, proveedor OSINT, exportación visual o ejecución activa.

Para un PR que cruza una frontera: indicar riesgo, control, test positivo/negativo y evidencia de ejecución. Si el control se difiere, marcarlo como bloqueo de despliegue cuando afecte confidencialidad de proyectos o alcance de red. La revisión humana de otro integrante sigue siendo obligatoria. Los criterios [ASVS](https://owasp.org/projects/asvs) se seleccionarán por funciones efectivamente implementadas; no declarar “cumplimiento ASVS” sin trazabilidad y prueba de todos los requisitos aplicables.
