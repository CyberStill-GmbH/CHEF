# Backlog propuesto para CHEF web

**Borradores; no son issues creadas ni tareas aceptadas.** El [plan Scrum](2026-09-scrum-to-oct31.md) limita octubre a ~103 h netas y deja abierta la priorización de despliegue. Cada issue debe tener owner humano, reviewer distinto, tamaño ≤8 h, fuente/permiso, Given/When/Then positivo y negativo, prueba y enlace a requisito/ADR. No asignar cuentas a Diego/Jhojan sin sus logins. El trabajo aceptado de núcleo/CLI no se factura otra vez.

## Gate 0: decisiones

1. **Validar frontera Node–Go y acceso a datos** — César con review Diego/Jhojan. Given stack confirmado Node.js/Prisma/OAuth + motor Go y core TS existente, When se prueba job versionado por `stdin/stdout`, Then documentar límite, timeout, coste, empaquetado y conformidad sin cambiar CLI. Negativo: crash/salida inválida no publica parcial; Go no adopta Prisma ni credenciales. Fuente: [ADR 0011](../adr/0011-node-go-boundary.md).
2. **Verificar primera fuente pasiva** — Jhojan con review César. Given Common Crawl Index seleccionado, When se documentan acceso, términos, datos, cuota, frescura y permiso para dominio autorizado, Then generar fixture reproducible y confirmar o descartar primer conector. Negativo: si no hay fuente confirmada, usar fixture sintético declarado; ninguna consulta real se simula como ejecutada. Fuentes: [índice](https://index.commoncrawl.org/), [selección](../research/open-osint-selection.md).
3. **Cerrar corte de demo y hosting** — César, Diego y Jhojan. Given 10 h/semana por persona y acceso Vercel/Railway, When se estima web local vs privada desplegada, Then aceptar historias que quepan y fijar pantalla objetivo. Negativo: no declarar multiusuario si no se ha probado aislamiento/sesión/despliegue. Fuentes: [Vercel](https://vercel.com/docs/frameworks/frontend/vite), [Railway](https://docs.railway.com/guides/saas-backend).

## Vertical web, en orden de dependencia

4. **Contrato TS↔Go, observación multifuente y snapshot** — César, review Jhojan. Given Nmap y fixture pasivo elegido, When se propone job/resultado o campo nuevo, Then schema, ejemplos TS/Go, pruebas de conformidad y compatibilidad; preservar IDs y cadenas Evidence/Observation. Negativo: ID duplicado, referencia rota o salida Go inválida falla de forma atómica. Fuente: [ADR 0011](../adr/0011-node-go-boundary.md).
5. **Proyecto y aislamiento PostgreSQL/Prisma** — César, review Diego. Given proyectos A/B, When se importa/consulta/exporta en A, Then B no ve ni modifica sus datos. Negativo: manipular projectId o ID de asset produce denegación. Fuente: [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html).
6. **API de importación con núcleo actual** — César, review Jhojan. Given XML Nmap autorizado y policy, When la API invoca `ImportEvidence`, Then persiste run/snapshot y devuelve estado; CLI conserva comportamiento. Negativo: archivo grande/hostile/scope inválido no publica parcial. Fuente: [Nmap XML](https://nmap.org/book/output-formats-xml-output.html).
7. **Limpieza Nmap auditable** — Jhojan, review César. Given duplicados, estados ambiguos y hostname compartido, When se normaliza, Then vista muestra recuentos/razones y conserva evidencia; `open|filtered` no se presenta como `open`. Negativo: no fusionar hosts por hostname. Fuente: [estados Nmap](https://nmap.org/book/man-port-scanning-basics.html).
8. **Conector pasivo autorizado** — Jhojan, review César. Given fuente y permiso documentados, When se importa/consulta, Then guarda fuente, locator, tiempo, límites y error; nunca amplía scope. Negativo: cuota, respuesta malformada o acceso denegado no generan observaciones ficticias. Fuente según issue 2.
9. **Motor Go de enlace activo–pasivo explicado** — César, review Jhojan. Given servicio Nmap y señal pasiva del mismo dominio/IP, When Go compara claves tipadas/tiempo, Then vínculo fuerte o candidato incluye regla, evidencia y fechas reproducibles. Negativo: coincidencia débil no confirma identidad ni vulnerabilidad; timeout/crash no altera datos publicados. Fuente: [ADR 0011](../adr/0011-node-go-boundary.md); [estudio](../research/recon-correlation-2026-09.md).
10. **Explorador React accesible** — Diego, review César. Given proyecto con observado/candidato/conflicto, When se elige relación en grafo o lista, Then panel muestra explicación, fechas, fuente, hash/locator y enlace a exportación. Negativo: texto importado no ejecuta HTML/URL; teclado y estados vacíos funcionan. Fuentes: [React TS](https://react.dev/learn/typescript), [guía de explorador](../../.agents/skills/chef-explorer/SKILL.md).
11. **GitHub OAuth y membresías** — César, review Diego. Given usuario sin pertenencia a proyecto, When inicia sesión, Then ve solo sus proyectos; tokens/secretos permanecen servidor. Negativo: callback inválido, sesión expirada o IDOR se rechazan. Fuente: [GitHub OAuth](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).
12. **Exportación descargable versionada** — Diego + César, review Jhojan. Given proyecto con relaciones, When se exporta, Then snapshot/esquema/referencias y manifest de filtros son legibles y reproducibles. Negativo: archivo ajeno/proyecto ajeno no se descarga. Fuente: [contrato](../contracts/README.md).
13. **Despliegue privado y operación** — César + Diego, review Jhojan. Given servicios preparados, When se despliega a Vercel/Railway, Then login, importación, DB, export, migración, backups y logs seguros funcionan en URL de equipo. Negativo: fallo de DB o OAuth muestra error recuperable; no se exponen secretos. Fuentes: [Vercel](https://vercel.com/docs/frameworks/frontend/vite), [Railway](https://docs.railway.com/guides/saas-backend).
14. **Experimento de ahorro** — Diego, review César. Given XML + fuente pasiva y rúbrica previa, When evaluadores alternan CHEF/manual, Then registrar tiempo, pasos, errores, falsos enlaces y muestra real. Negativo: resultado adverso se conserva. Fuente: [hipótesis](2026-09-scope-decision.md).
